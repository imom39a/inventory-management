1. System overview

Two processes talk over HTTP on localhost. The server holds all data in memory for the life of the process, including Restock Orders created at runtime.

3. Server

main.py · 389 lines

Routes, models, and filters

  • Pydantic models for inventory, orders, demand, backlog, purchase orders, and the restocking request and response shapes
  • Filter helpers: apply_filters, filter_by_month, QUARTER_MAP
  • Route handlers for every endpoint. Restocking routes are thin and hand off to restocking.py
  • CORS set to allow all origins

restocking.py · 192 lines

Restocking domain logic

  • build_candidates, allocate, create_orders, list_orders
  • Holds restock_orders in a module-level list, guarded by a threading.Lock on create
  • Raises RestockValidationError, which main.py maps to 400
  • Single now() clock so tests can freeze time

mock_data.py · 39 lines

Data loader, runs at import time

  • Reads each JSON file once, into module-level lists and dicts
  • Spending is split into summary, monthly, and category pieces
  • Changes to JSON require a server restart

4. Client

Shell

main.js → App.vue

Vue Router in history mode, seven routes. Route meta.hiddenFilters lets Restocking hide the period and status filters. App.vue holds nav, FilterBar, profile menu, and the tasks modal.

Views

views/*.vue (7 pages)

Each page fetches on mount and on filter change, holds raw data in refs, and derives display data in computed properties.

Shared state

composables/*.js

useFilters, useAuth, and useI18n are module-level singletons. Locale is persisted to localStorage.

Pure helpers

utils/*.js

csv (escape and download), inventoryExport (rows and filename), currency. No Vue imports, unit-tested directly.

api.js · 134 lines

Central HTTP client

Hard-codes the base URL and builds query strings from filter objects, dropping 'all'. Now also wraps the restocking recommendations and Restock Order routes. Every page but Reports reads data through it.

Views and modals

Pages with detail modals

Views open detail modals for product, backlog, inventory, and cost. Restocking.vue uses RestockBudgetPanel. Orders.vue lists submitted Restock Orders. Reports.vue still skips api.js and calls Axios directly with its own URL.

7. Observations from reading the code

These describe the current state. They are not refactor proposals.

  • Client calls with no server route. api.js calls GET/POST /api/tasks, PATCH/DELETE /api/tasks/{id}, and /api/purchase-orders. App.vue calls the tasks endpoints. Expected 404. Unchanged since the first draft.
  • Dead purchase-order client methods. createPurchaseOrder and getPurchaseOrderByBacklogItem have no callers in the client. Restock Orders now cover the replenishment flow, and GLOSSARY.md lists "purchase order" as a term to avoid.
  • Restock Orders are not persisted. They live in a module-level list in restocking.py and are lost on server restart. Fine for a demo, but it is the only state the app writes.
  • Quarter logic in two places. QUARTER_MAP drives filtering. /api/reports/quarterly hard-codes its own 2025 quarter branches.
  • Date filtering by substring. order_date is matched with in. Works for the bundled data format.
  • Hard-coded API base in two places. api.js and Reports.vue both name http://localhost:8001/api.
  • CI does not run tests. The suites in section 6 run locally only. The GitHub workflows run Claude review, not pytest, Vitest, or Playwright.
  • Glossary and specs exist, ADRs do not. GLOSSARY.md defines Order, Restock Order, Reorder Point, Restock Candidate, and Recommendation. docs/specs/ holds the restocking spec. There is still no docs/adr/.
  • Open CORS and no auth. allow_origins=["*"] with no authentication. Stated as demo-only in server/CLAUDE.md.
